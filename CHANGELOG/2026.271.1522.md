### Revision note: the box-composition example (fixes the round-1 BLOCK)

The round-1 verdict BLOCKed block 1 on the README box example, reading the
lead-in "a box's `candy:` list" as contradicting the snippet's nested
`candy: { base:, candy: [...] }` shape. The nested shape is the **real** box
schema, not an error: a box is a `candy:` mapping carrying `base:` plus a nested
`candy:` list of refs. Evidence:

- A validated box in this org uses exactly that shape — `opencharly/layer-agentteams`
  `box/agentteams/charly.yml`:

  ```yaml
  agentteams:
      candy:
          version: 2026.243.0300
          base: cachyos-base
          description: |-
              ...
          candy:
            - '@github.com/opencharly/layer-supervisord:v2026.240.0121'
            - agentteams
  ```

  and `charly box validate` on that repo reports
  `OK — checked 64 candies, 4 boxes, 2 deploys, ...; 0 warnings, 0 errors`.

- The merged wave-1 template (`opencharly/layer-ripgrep` README, on `main`) uses
  the identical nested snippet, and its own `candy` gate passed.

So the snippet was already schema-correct; the **prose** was the divergence. The
fix aligns the prose to the schema: the lead-in now reads "a box is a `candy:`
mapping that carries the box's `base:` image and a nested `candy:` list of layer
refs", and the snippet annotates `base:` and the nested `candy:` inline. No
snippet semantics changed, so this re-push is a one-commit prose correction of
the same docs-only diff.
